# Text / message analysis (same system as video analysis)

## When to use

The user sends, forwards or pastes text — a Telegram message, a forwarded channel post, a screenshot of a post, a chat fragment, an article, a document, a voice message — and asks for analysis (or the analysis is implied by the standing preference). Apply the same tag system as `youtube-content`; load that skill's marking table if the tags are not in context. AUTO-TRIGGER: any multi-paragraph text (more than one paragraph) sent for analysis runs this skill without being asked. Single-paragraph messages and one-line questions do not. Exception: for attached text files and long external posts the skill first asks for confirmation — see Input forms below.

## Input forms: files and long external posts

- **Текстовый файл** (.txt, .md — скинут в бот) и **длинный пост из другой группы** (пересланный или вставленный, ≥2 абзацев): НЕ анализировать сразу. Сначала — вопрос-подтверждение через форму с кнопками: вопрос «Показать Brain Hack?» (для англоязычного чата — «Brain Hack analyze?»; язык = язык общения чата), ровно две кнопки: «Показать» и «Отмена».
- **«Показать»** → полный анализ: `../youtube-content/scripts/psych_layer.py --file <path>` (или stdin) — маркеры, классификация по абзацам (каждый абзац приходит с полем `subtype`) и retrieval одним JSON — затем разметка по обычному формату. Роутинг подтипа: пропагандистские метки классификатора (Flag_Waving, Appeal_to_Fear-Prejudice, Guilt_by_Association, Appeal_to_Hypocrisy, Slogans, Appeal_to_Time) → ⚫ 📢🧠; НЛП-инструментарий из маркерного слоя (пресуппозиции по Левинсону, номинализация и удаление агента, эпистемическая дистанция) → ⚫ 🔪🧠; остальные метки (loaded language, doubt, false dilemma, exaggeration, appeal to authority…) → ⚫ 🎭🧠; расхождение слоя со своей разметкой — показать оба вердикта; слой недоступен — тихая деградация к обычным проходам.
- **«Отмена»** → ничего не делать: анализ не запускать, файлов не читать, ответить коротким подтверждением без разбора. Повторный заход — только по новой присылке или явной команде.

## Output format

1. **Source line** first: the link (if any), otherwise `источник: <chat/channel/author>, <date>` — for forwarded posts name the original author/channel, not the forwarder.
2. **Summary by thought** — split the text into logically complete thoughts (one idea per unit: a claim + its support, a remark, a conclusion). For EACH thought: its indicator emoji, then a 1–3 sentence summary of what that thought says. No timestamps and no paragraph numbers for text — the thought itself is the locator (quote 2–5 words of it if needed to identify).
3. Order = order of appearance in the text, one block per thought, never grouped by tag. If a thought mixes categories, put the primary indicator on its own line and note the others inside the summary. If the source has real timestamps (video/screenshot with timecodes), keep the `EMOJI [MM:SS–MM:SS]` format — timestamps are for video only.
4. Deliver in chat/Telegram. Never write files unless the user explicitly asks. Telegram caps one message at 4096 chars: measure the assembled answer programmatically, shorten the longest thought descriptions first, and only split into parts if still over — then the chat reply is a short confirmation, not a repeat of the parts (same rule as `youtube-content`).

## RAG (psychology index)

Before marking, query the local psychology index — one call per analysis:

- MCP tool `psychology_search(query, top_k)` (server `psychology-rag`, stdio, venv `~/.hermes/tools/psych-rag-env`), or the CLI `scripts/rag_query.py "<text>"`.
- Corpus: `psychology/devices.json` (the closed device list — draft, 70 entries: 36 logical + 14 Dilts language focuses + 11 внушение + 9 сквозные/уровень текста) + `psychology/psychology/…fb2` book chunks (1200 chars / 200 overlap, section titles kept as labels). Storage: SQLite FTS5 (`docs_fts`, `content='docs'`, `content_rowid='id'`, колонки `label` и `text` с весами 2.0/1.0) + vectors, hybrid `0.4·BM25 + 0.6·cosine`, +0.15 boost for exact device-name hits, top_k 6, min_score 0.30, output ≤2500 chars. Measured live on this machine (2026-10-19, ~9k docs): FTS5 lexical half ~1 ms per query — раньше это был полный проход по корпусу (~300 ms); cosine-матрица пересобирается на каждый запрос (~10 ms); тёплый запрос целиком 55–65 ms. Полный проход оставлен как fallback для БД без FTS5-индекса. Один запрос на всех кандидатов вместо SELECT на каждый документ. Recall: прежний проход сканировал только `text`, поэтому запрос по имени устройства находил определение лишь когда имя случайно было в определении; с колонкой `label` контрольный запрос «ложная дилемма» даёт top-hit=device «Ложная дилемма» вместо чанка книги. Numbers drift with the corpus — re-measure before quoting them, recipe in `local-rag-on-weak-hardware`.
- Corpus enrichment procedure (sourced examples per device, dedupe against existing definitions, attribution rules): `references/corpus-enrichment.md`. Fine-tuning pipeline for the classifier layer (dataset construction, split, thresholds, memory budget, promote gate): `references/fine-tuning-pipeline.md`.
- `psychology/devices_enriched.json` — per-device supplement: `en_name` (English equivalent, used for English-source retrieval), `examples` (real usage examples, each with source URL), `extra` (facts that do not duplicate the existing definition). When quoting a device definition in an answer, cite the source URL from this file; never present a sourced example as your own reasoning. Devices whose examples are definition-level only (5: impression management, cumulative framing, emotional escalation, pre-emptive inoculation, appeal to common sense) must be attributed as theory, not as observed in the text.
- Measured (fastembed ONNX `paraphrase-multilingual-MiniLM-L12-v2`, 384 dims): warm model load ~0.6 s; a warm query ~55–65 ms at the current corpus size (the cosine matrix rebuild dominates now, the FTS5 lexical half is ~1 ms), a cold CLI call ~1.5 s. The plugin path spawns a subprocess per inbound message, so it pays model load on every message (~1.5 s retrieval + ~0.9 s classifier + ~30 ms markers); the fix is one persistent worker shared by plugin, CLI and MCP server, which brings a message to ~50 ms. Report cold and warm numbers separately.
- Тёплый worker — `scripts/worker.py` + `scripts/worker_client.py`: один живой процесс держит fastembed и ONNX загруженными, отвечает JSON-lines (ping / search / markers / classify), и через него ходят плагин и psych_layer. Живой замер через плагин: первое сообщение 3.9 с (запуск worker и загрузка моделей), каждое следующее — 84 мс; прежний путь был subprocess на сообщение (~2.7 с). Клиент перезапускает мёртвый процесс один раз; если worker не поднимается, вызывающий идёт прежним subprocess-путём — деградация, а не отказ анализа. Тесты `WorkerTests` идут без моделей (`PSYCH_WORKER_NO_MODELS=1`).
- BM25-only fallback (`--no-embed`, pure stdlib, ~0.3 ms) when ONNX cannot run — results are lexical-only, the skill still works.
- Боковой канал для мовы — `scripts/side.py`, отдельный от основного языка. `norm_words` остаётся `[a-zа-яё]` и индекс НЕ перестраивается: боковые слова (і, ї, є, ґ, ў) приводятся к русской форме только на стороне запроса (`q_tokens`), чтобы запрос на мове попал в существующий русский индекс. Мова — сигнал (вставка в русскую речь = признак токсичности и враждебности), а не язык корпуса: боковой канал не участвует в scoring корпуса, и закрытый список устройств (`devices.json`) под мову не расширяется. Проверено: sha256 и mtime индекса совпадают с прежними (пересборки нет); «маніпуляцыя» → «манипуляция» (df 164) вместо фрагмента «пуляцыя» (df 0). Ограничение: приведение — графика плюс окончания («цыя»→«ция», «ця»→«ца»), морфологию и перевод оно не делает: «найкращий» ≠ «лучший», «маніпуляції» ≠ «манипуляция»; словарного перевода нет. Eval-маркеры не изменились (27.7 / 41.5 / 30.8 / 20.0 / 93.3) — боковой проход им не измеряется, в eval_set нет украинских примеров.
- The `psych-rag` plugin (`pre_gateway_dispatch`) appends three blocks to multi-paragraph inbound messages automatically: the retrieved passages, the marker hits from `scripts/markers.py`, and — only when markers fired — the classifier's second opinion. Single-paragraph messages are not rewritten. Gate (реальный, не объявленный): абзацев ≥2 и ≤12 (`MAX_PARAS` применяется), длина ≤4096 символов (`MAX_CHARS` = фактический лимит платформы; прежние 4000 означали, что сообщения 4001–4096 не разбирались вообще и это выглядело как пропуск анализа, а не как отказ гейта). Абзац — каноническое определение из `markers.paragraphs` (строка до перевода строки); плагин больше не держит своё, поведение то же, но источник один. Все три слоя получают полный текст сообщения до порога гейта (4096 символов), а не первые 1500: раньше сигналы после 1500-го символа были невидимы, и сообщение между 1500 и порогом проходило гейт, но не анализировалось. Замер: 1725-символьное сообщение с маркером на позиции 1655 — на полном тексте 2 маркера, на прежнем срезе 0. Таймаут retrieval поднят до 2× (полный текст ~6.2 с против 3.2 с на срезе). Маркеры запускаются через venv-интерпретатор, а не через системный `python3` (на 3.9 PEP 604 падает). Классификатор вызывается с `--min 0.70` (операционная точка правила); без этого применялся только порог thresholds.npy, 14 из 23 которых ниже 0.70.
- Retrieval supplements the list, it never replaces it: a device that exists in the list but not in the corpus must still be applied from the list.

## Тесты

`scripts/tests/test_layers.py` (unittest, stdlib; ONNX/HF не грузятся — модели подменяются фиксами). Запуск:
`/Users/alex/.hermes/tools/psych-rag-env/bin/python scripts/tests/test_layers.py`

Два блока:
- **A — регрессия на исправленном** (фактическое число — по прогону; на 2026-10-19: 53 теста, все проходят): пара у repetition-метки, гейт по повтору, кускование длинного абзаца (метка из хвостового куска), позиции `window()` на строке, меняющей длину при `lower()`, `limit=0 → None` в telegram-пути, границы слов и переворот отрицания в лексиконе, словарь и границы `ukr_detect`, `--chunk` у обоих вызывающих rag_query.
- **B — правила, которые кодом не реализованы** (список расхождений; на 2026-10-19 все его тесты проходят — правила реализованы и тесты перешли в блок A): гейт 4000 против фактического лимита 4096; операционная точка 0.70 (14 из 23 порогов ниже, `--min` никто не передаёт); три разных определения треда (лексикон = корень+все потомки, telegram = reply_to, rutube = parent_id) и два определения «среднего по тредам» (простое против взвешенного); правило имён собственных; фрагменты ≤3 слов; amb в доле не-русского; дубликат стема «не надо»; порядок ничьи; недостижимые правила END_MAP; отсутствие порога у `side_share`; расхождение side/ukr_detect; AMBIG и WEAK, которые собираются, но не участвуют в вердикте; контроль 4096/429 у status_post; None-метка в neural_pass; `language:`-теги в фильтре языка; обещанное поле `language` в выводе fetch_transcript; отсутствие chunk в rag_mcp.

Тесты блока B не чинят баг — они фиксируют расхождение правила с кодом и должны начать проходить после исправления. Блок B — живой список расхождений: источник правды — тесты, а не проза навыка; перед коммитом прогонять оба блока и писать, сколько падает. Когда пункт B починен, его тест переходит в блок A — закреплённые числа тестов не являются фактом, писать фактическое число падающих. Замер слоя (`scripts/eval_markers.py` на `psychology/eval_set.json`) — отдельный, in-domain; живые цитаты в него не смешивать.

Правила написания тестов этого набора (без них тест даёт ложеловный «успех»):
- Фейк ONNX обязан возвращать `[np.array([logits])]` — вызов `run(...)[0][0]` ждёт 2-D: список падает на `unary -: 'list'`, 1-D массив даёт скаляр и `enumerate` не работает.
- Фейк должен срабатывать только на куске, где есть целевое слово (декодировать id обратно в слова через свою карту): иначе он даёт метку на каждом куске, и поведение на границе куска не наблюдаемо.
- Тест маркеров строится из слов, которые реально есть в `markers.json`, и с пробелом перед совпадением: `(?<!\w)` не сработает, если слово приклеено к буквам; assert по точной длине pad-окна (pad 30 → 29 символов перед словом при старте на позиции 43).
- Отсутствующую константу проверять через `getattr(mod, "CONST", None)`, необязательный импорт — через try/except + `skipTest`: тест должен FAIL с формулировкой правила, а не ERROR с AttributeError.
- Каждый тест блока B обязан доказывать расхождение кейсом, где «как есть» и «по правилу» дают РАЗНЫЙ результат; тест, который проверяет только наличие строки в исходнике, помечать как проверку guard-а, а не как доказанный баг. В отчёте называть, какие модули тестируются поведением, а какие не тестируются вообще (retrieval-путь, парсеры комментариев, сетевые скрипты) — поведенческих должно быть больше, чем строковых, и их соотношение видно в отчёте.
- Сетевой скрипт становится тестируемым только когда у него есть offline/dry-run режим (печатает, что отправил бы) и mock-transport в тесте; без него тест вынужден проверять текст исходника и проходит, когда логика сломана.
- Тест двухслойного роутинга строится на кейсе, где срабатывают ОБА слоя (маркер + вердикт модели): кейс только с моделью не доказывает атрибуцию абзаца, кейс только с маркером — что вердикт вообще участвует. Живая проверка (не spy) обязана идти на тексте, где оба слоя реально сработали, и печатать оба результата.
- Словарные списки навыка (маркеры, лексикон, словари мовы, списки слов тегов) проверять на латинские буквы внутри кириллических слов перед коммитом: homoglyph не даёт синтаксической ошибки и не ловится тестом — слово просто никогда не совпадёт, и правило молча перестаёт работать.
- Spy-тест работает только когда вызывающий модуль импортирует тот же объект модуля: патчить атрибут (`markers.scan`, `classifier.classify`) и восстанавливать в `finally` — локальная подмена в тесте вызывающему не видна.
- Импорт, нужный тесту, обязан быть добавлен в шапку тестового файла: условная замена `if anchor in t` молча не применяется, и тест падает с NameError на импорте, который не был добавлен. Якорь проверять счётчиком (`assert t.count(anchor) == 1`) перед заменой.
- Новый модуль навыка обязан читать файлы через `with open(...)` — тест `test_readonly_db_and_closed_files` сканирует скрипты на незакрытый `open()` и падает на модуле, который его не закрыл.
- Блок A несёт `TagRuleTests` — поведенческие тесты на теги комментария: порог 🤢 (не любое ненулевое значение), ☠️ только на смерти человека (техника и животные — не ☠️), пара подтипа вместо имени устройства, честная строка о недоступном нейро-слое. Каждый пункт аудита — отдельный тест и отдельный коммит.

Формат отчёта об аудите (запрос «какие баги остались»): три уровня — критичные (меняют доставляемый результат анализа), мажорные (меняют цифры или поведение в отдельных случаях), минорные (мёртвый код, декоративные наборы, расхождение docstring с фактическим выводом). Каждый пункт — с замером или кейсом, доказывающим разный результат; без замера — не пункт, а предположение. Проверять весь набор скриптов навыка, а не только тот слой, о котором спрашивали в прошлый раз: расхождения живут и в путях доставки (telegram, rutube, статус-пост), и в вызывающих retrieval.

## Rules

- Источники для ⚫: закрытый список приёмов — `references/manipulation-devices.md`; корпус (книга по манипуляциям в `psychology/` — FB2 + извлечённый текст) опрашивается retrieval-ом по правилам `local-rag-on-weak-hardware`. Статическая карта списка подаётся всегда, retrieval добавляет определения и примеры из корпуса — так список не «плывёт» от запроса к запросу.
- ⚫ requires an explicit call-out: name the device and the specific error («подмена: X выдаётся за Y», «ложная импликация: из A не следует B», «ложная дилемма», «апелляция к страху», «ошибка выжившего»). Формат: `⚫ 🔪🧠 <мысль>` для НЛП-приёмов, `⚫ 🎭🧠 <мысль>` для манипуляций, `⚫ 📢🧠 <мысль>` для пропаганды; ⚫ без пары — незавершённая метка. Если фрагмент одновременно содержательный и манипулятивный — ⚫ в таймлайне, другая категория в описании.
- Двухслойная детекция: текст не обязан содержать название приёма или слова из корпуса. Слой 1 — `scripts/markers.py` + `psychology/markers.json` (детерминированный, без LLM): триггеры пресуппозиции по Levinson (definite descriptions, factive/implicative/change-of-state verbs, iteratives, verbs of judging, temporal clauses, clefts, comparatives, counterfactual conditionals, wh-questions), модальность и эпистемическая дистанция (absolutes, hedging, evidentiality gap), номинализация и удаление агента, оценочная/эмоциональная лексика, структурные маркеры (imperative+benefit, benefit to speaker, disclaimer, narrative markers, universal from single case, repetition, question trap). Слой 2 — retrieval даёт определение приёма. Вывод строится из маркера + определения, а не из совпадения слов с RAG: маркер показывает, что именно в тексте делает фразу приёмом.
- **Подтип решается общим модулем `scripts/tag_routing.py`** — один словарь для обеих путей: путь текста (`psych_layer.py`) и путь комментариев (`comment_analysis.py`). Приоритет: уже пара → семья сработавшего маркера → метка классификатора по имени → семья устройства из `devices.json`. Имя устройства без пары — незавершённая метка: `pair_for_device` возвращает None и тег не ставится. Метки словаря обязаны совпадать с фактической таксономией модели (23 метки), а не с вариантом списка. Семья «Фокусы языка: …» (Дилтс) ловится маркером «фокус» → 🔪🧠; без него фокус Дилтса молча уходил в 🎭🧠.
- «Приём» в блоке комментариев возможен только когда модуль сам строит пары по маркерам + вердикту классификатора (`device_pairs()` через tag_routing, вызывается по умолчанию): вызывающие пути не передают `device_by_text`, и без этой wiring приоритет «приём» никогда не срабатывал.
- НЛП-маркерные пакеты: семьи «НЛП: …» и «Фокусы языка: …» дают точную атрибуцию устройств (якорение, внушение, фокусы Дилтса — имя устройства прямо в candidates маркера). Схема families жёсткая: значение маркера — список стемов, которые сканер ищет в тексте; атрибуцию устройства кодировать в ИМЕНИ маркера («Устройство: паттерн»), а не в значении — иначе сканер ищет в тексте название устройства и пакет молча даёт нулевой recall. Значения `MAP` обязаны быть реальным именем устройства ИЛИ реальным семейством `devices.json` — проверять через `unknown_map_values()` и `unmapped_families()` (печатается в eval-отчёте); прежние значения «логические», «эмоциональные» и «внушение (книга)» таких семейств в devices.json не имели и никогда не могли совпасть с candidate-именем. Замер на `psychology/eval_set.json` — скрипт `scripts/eval_markers.py`. Цифры слоя на **in-domain** примерах (55 positives): exact 32.7%, family 43.6%, пропуск 23.6%, FP на нейтральных контролах 20%, роутинг подтипа 93.3%. На весь набор (65 positives, включая 10 живых цитат с источником) — exact 27.7%, family 41.5%, пропуск 30.8%; на живых цитатах exact 0% (живые примеры — более трудный набор, не регресс). Прежняя цифра family ~40% мерилась против словаря, в котором был фальшивый ключ «логические» — после исправления MAP она поднялась до 43.6% на in-domain. На реальных цитатах из источников тот же слой даёт near-zero exact recall: лексически ненаблюдаемые приёмы («структура вывода», «данные», «язык», все сквозные) — зона RAG + LLM, и это граница слоя, а не его поломка. Правило замера: подавай in-domain и real-world подмножества отдельно, никогда не смешивай в одно число; падение общего recall после добавления живых примеров — не регресс, а более трудный набор, и называть его регрессом нельзя. Не выдавай in-domain цифры за точность на живых текстах.
- Слой 3 — независимое второе мнение: `scripts/classifier.py` (XLM-RoBERTa-large, 23 метки SemEval-2023 Task 3, ONNX int8 `psychology/models/classifier_int8.onnx`, пороги `thresholds.npy`, перевод меток через `psychology/taxonomy_map.json`). Русский вход идёт напрямую, переводить текст на другой язык нельзя — перевод разрушает лексические доказательства слоя 1. Гейчится слоем 1: запускается только на абзацах, где маркеры сработали. Стоимость: загрузка 0.5 с, 19 мс на абзац в тёплом процессе, пик ~1.3 ГБ RAM. Классификатор не авторитет (fine-grained F1 ~0.45): он никогда не перекрывает закрытый список и маркеры; при расхождении показывать оба («классификатор видит X, по маркерам это Y»), цитата-доказательство из маркерного слоя обязательна. Подробности и замеренное сравнение кандидатов — `references/classifier-layer.md`.
- **`classifier.classify()` как модульная функция НЕ несёт поля `para`** — его добавляет тёплый worker. Роутинг, привязанный к абзацу, обязан приписать абзац явно: для единицы из одного абзаца (комментарий) это абзац маркерного hit-а; иначе пары склеиваются по ключу `None`, и вердикт модели уходит не в тот абзац (замер: `device_pairs(hits, rows)` дал `{None: '🎭🧠'}` вместо пары по абзацу 1).
- Гейт слоя 3 сохраняется и в пути комментариев: без сработавшего маркера классификатор не вызывается и пара не ставится — это правило, а не поломка, и «чинить» его нельзя (тест обязан проверять обе ветки).
- Гейт слоя 3 берёт абзац из индекса hit-а (`para`), а не из подстроки: у `repetition` поле `found` — склеенная строка слов («видит, качество, цену»), которой нет ни в одном абзаце, и абзац, помеченный только повтором, раньше до модели не доходил (замер: 2 абзаца, гейт давал только абзац 2). Теперь каждый hit несёт свои абзацы, и повторный абзац проходит.
- Абзац длиннее 256 токенов режется на куски и проходит целиком, а не отбрасывается: раньше `enc.ids[:256]` молча резал хвост, и приём после 256 токенов был невидим (замер: абзац 2550 токенов с подменой в конце → пустой результат; тот же приём отдельным абзацем → Doubt 0.704). По каждой метке берётся максимум вероятности между кусками, порог `thresholds.npy` применяется к этому максимуму; в JSON есть поле `chunk`, откуда взята метка.
- RAG-запрос опрашивается кусками по 1500 символов (плагин и `psych_layer`): embedding-модель сама видит только ~512 токена, поэтому устройства из хвоста длинного текста раньше не находились. Замер на тексте 3811 символов: полный запрос (chunk 1500) даёт «Ложная дилемма» на позиции 3739, срез 1500 — нет. Модель загружается один раз, вектора считаются по всем кускам сразу.
- Единица абзаца общая для всех слоёв: `markers.paragraphs()` — строка до перевода строки (пустые строки пропускаются), её используют markers, classifier, psych_layer и plugin. Раньше psych_layer делил по пустной строке, и индексы абзацев не совпадали с классификатором. В JSON `classifier.py` отдаёт полный текст абзаца (обрезка 80 символов осталась только в человекочитаемом выводе) — иначе маркер после 80-го символа абзаца терялся при сопоставлении с `subtype`. `psych_layer.py` гейтит классификатор слоем маркеров по умолчанию (как plugin); `--no-gate` — для сверки цифр; результат несёт поля `paragraphs` и `gated`.
- Версия модели закреплена в `psychology/models/model_version.json` (id + revision + формат). При первом использовании в сессии `scripts/model_update_check.py` сравнивает записанную версию с hub и ищет схожие модели с лучшим заявленным метриком, покрывающие русский. В плагине формулировка точнее: один раз на чат и не чаще раза в сутки (`RECHECK_SECONDS = 86400`), ключ — `(platform, chat_id)`, потому что границы сессии плагину недоступны (нет доступа к session key) — раньше флаг был один на весь процесс и новый чат не получал проверки. Если нужно обновление — состояние помечается как нужное (`update_state.json`), загрузка идёт в фоне (`model_update_run.py`), новая модель проверяется на трёх контрольных текстах. Текущая модель продолжает работать, пока новая не проверена; молча менять модель нельзя — продвижение только явное (`model_promote.py`). Если обновление начато, сказать это явно: «начато обновление психологической модели, продолжается использование старой».
- Пороги — свойство конкретной модели, а не общее. Кандидат без своих порогов не оценивается по порогам живой модели: сравнение на контрольных текстах идёт по его же `thresholds.npy`, а при их отсутствии — по фиксированной рабочей точке 0.70, и состояние помечается `needs_calibration` (калибровка обязательна перед продвижением). `model_promote.py` отказывается продвигать модель, у которой пороги отсутствуют или байтово идентичны порогам живой модели (это пороги другой модели), и проверяет, что длина порогов совпадает с числом меток; обход — только `--force`. Метки тоже берутся из каталога каждой модели: при разных наборах меток сравнение по имени некорректно (нужен перенос через `taxonomy_map.json`). `classifier.py --min` требует значение — usage-сообщение вместо IndexError.
- Сквозной проход обязателен после по-мыслового: отдельный блок «Сквозной разбор» для приёмов, которые существуют только в сочетании абзацев (подводка/priming, накопительный фрейминг, отложенный вывод, нарративная дуга, эмоциональная нарастающая, преёмпт-инокуляция, апелляция к здравому смыслу, селекция на уровне текста, повтор с вариацией). Приём, существующий только в сочетании абзацев, не приписывается одному абзацу; абзац-подводка маркируется как подводка с указанием, какой вывод она готовит. Для каждого сквозного приёма перечислить участвующие мысли (2–5 слов цитаты из каждой) и вывод, который они вместе строят. Gate-тест применяется на уровне текста: если убрать рамку, вывод перестает следовать.
- Gate for ⚫: strip the emotional/rhetorical frame and leave only the facts — if the conclusion no longer follows, it was induced by a device, so ⚫; rhetoric without a conclusion is not ⚫. Device names and the working closed list: `references/manipulation-devices.md` (confirm scope with the user before treating it as exhaustive).
- Разграничения: 🍏 (факты) vs 🐻 (без фактов, эмоционально); 🦅 (идеализация без аргументов) vs нейтральное сравнение с цифрами; 🐷 (явная похвала) vs нейтральное сообщение об ударах; 🦹 (тезис против теории + продажа курса) vs корректный экономический анализ; 🟤 (реклама) vs самопиар; нейтральная политика (законы, выборы как факты) не маркируется.
- Ложное или одностороннее утверждение само по себе не ⚫ — ⚫ только за сам логический приём.
- Факты в тексте не выдумывать: если автор что-то утверждает без источника, так и писать («без подтверждения»); проверяемые утверждения проверять и указывать, подтверждены ли они. Сокращения и инициалы автора (ВБ, ЗГТ, аббревиатуры компаний) читать как написано; если раскрытие неоднозначно — отдельной строкой указать, что это допущение, а не факт.
- Закрывать разбор строкой «Нет <метки>» — перечислить категории, которых в тексте не оказалось; это отличает «не было» от «не заметил».
- Метки — общий словарь с `youtube-content`: при изменении определения метки обновлять оба скилла, иначе текст и видео начнут размечаться по-разному.
- Слои не считают одно и то же совпадение дважды: вторичный (боковой) слой сообщает hit только когда основной его не покрыл.
- Правки плагина `psych-rag` вступают в силу только после перезапуска гейтвея: плагин загружается при старте процесса, а не по изменению файла — сказать это пользователю, а не молчать.
- Аудит слоя делать пробой, а не чтением: каждый пункт — правило + минимальный кейс, где «как есть» и «с фиксом» дают РАЗНЫЙ результат; совпали — баг не доказан. Проверенные правила и кейсы — `references/marker-layer-pitfalls.md`; после правки модуля пробой повторять только после `importlib.reload` (session kernel держит старый импорт).
- Скриншоты: читать через vision_analyze, цитировать формулировки автора дословно там, где это важно для оценки.
- Голосовые: расшифровка через voice-transcription, затем тот же разбор.
- Если в тексте нет ни одного маркируемого фрагмента — сказать об этом явно, а не придумывать метки.
- **Словарный слой мовы (`../youtube-content/scripts/ukr_detect.py`), правило пользователя, 2026-10-18:** решают буквы `ї/є/ґ` (их нет в русском и белорусском) против `ў` (нет в украинском) и словарь форм, которые пишутся иначе и в русском, и в белорусском. Порог — одно доказательство на фрагмент. Общие uk/be слова (`і`, `як`, `але`, `що`, `де`, `бо`) — доказательство «не русский», но язык не решают: при них без маркерных букв — `amb`, не угадывать. Фрагменты ≤3 слов язык не решают. Точность замерена на 290 постах kievreal1: ложного 🐷 на чистом русском нет (каждое решающее слово — форма, которой нет в русской орфографии); ошибки шли в другую сторону — украинское читалось как русское, и словарь это снял (было `ru` 53 из 290, стало `uk` 254 / `ru` 35 / `amb` 1, переклассифицированное проверено вручную). Оставшиеся 35 — посты-сигналки из одних названий населённых пунктов: их слой решить не может, это граница метода.
- **Имя собственное в украинской орфографии — не 🐷.** Если единственное доказательство — слово с заглавной буквы с ї/є/ґ (Євген, Григорій, Борщагівської — 245 вхождений в выборке), это фамилия или название, а не мова-вставка: писать «имя в украинской орфографии» без 🐷. 🐷 ставится только при втором доказательстве (ещё одно имя или словарное слово). Словарные слова с маркерной буквой (пожеж, станці, районі) доказательством остаются.
- **В словарь нельзя добавлять стем, совпадающий с русским словом** (`район`, `станц`, `курсу`, `уходу`, `електротранспорт`): префиксное сравнение ловит русское слово и даёт ложное срабатывание. Добавлять можно только формы, отличающиеся и от русского, и от белорусского. Полные правила и цифры — `references/ukrainian-mova-pass.md`.
- Записи о запросах идут в Obsidian vault (`База знаний о сообщениях/Сообщения/YYYY-MM-DD.md`) только если пользователь просит; сам разбор — в чат.
